# ulsan-energy-poc

울산 에너지 자급자족 플랫폼 **POC(껍데기)** — [energy-v2-frontend](https://github.com/routinecrew/energy-v2-frontend) 프론트를 그대로 가져와 백엔드·DB·인증 없이 동작하도록 만든 정적 사이트.

## 특징

- **백엔드 없음**: `src/api/client.ts` 가 네트워크 대신 `src/mocks/poc` 목업 라우터로 응답. 원본 `api/{domain}`·`hooks` 는 수정 없이 사용.
- **로그인 없음**: 로그인 화면의 역할 버튼(전기사용자 / 발전사업자 / 관리자)으로 바로 진입. 이메일을 입력하면 `admin@…`, `operator@…`, 그 외 → 전기사용자로 매핑.
- **정적 export**: `next build` → `./out`. Cloudflare Workers(정적 에셋)로 배포.
- **지도**: 통합관제 지도는 Mapbox GL(`src/components/ui/MapboxMapView.tsx`). 자체 mapbox 구현으로 교체 시 이 컴포넌트만 바꾸면 됨.

## 실행

```bash
npm install
npm run preview    # 운영 빌드 후 http://localhost:3030 — 화면 확인은 이걸로 (빠름)
npm run dev        # 개발 서버 — 페이지마다 첫 진입 시 컴파일하므로 느림(수 초). 코드 수정 중일 때만 사용
npm run build      # ./out 생성
npm run deploy     # build + wrangler deploy (Cloudflare 로그인 필요)
```

> Windows PowerShell 에서는 `&&` 대신 `;` 로 명령을 이어야 합니다. 예: `cd ulsan-energy-poc; npm run preview`

## 전력거래 흐름 (RE100 › 전력거래, 2026-10-02)

통합관제(발전소·용량) → 컨설팅(무료진단 검토) → 전력거래. 메뉴는 기능 WBS 2.1 항목 그대로, 순서는 흐름 그대로: 거래 신청 → 거래 이력(협의·대화, 성사) → 거래 승인(서명) → 계약 현황(유형별 계약) → 내 계약 → 변경·해지 → 수익·정산(세금계산서·청구서) → 문서 관리. 항목을 빼거나 더하지 않는다(바꿀 땐 먼저 근거로 설득). 계약 유형은 자가소비 · onsite 둘 다 신청한다. 상세는 같은 화면 위 창으로 열고 다른 메뉴 화면으로 넘어가지 않는다.

| 메뉴 (WBS) | 발전사업자 `/generator/…` · 관리자(SPC) `/platform/…` |
| --- | --- |
| 거래 신청 (2.1.1) | 계약 유형 카드(자가소비·onsite — 장점과 유의)를 먼저 고른 뒤 입력. 기업은 회원가입과 같은 말(기존 기업 선택 / 신규 기업 등록, 기업명 · 기업 주소) — 고르거나 입력하는 건 관리자만, 그 외는 로그인 값. 같은 유형의 무료진단을 불러오면 설치 용량·계약 기간·요금제·요금 기준·단가·담당자가 채워지고 [불러오기 취소]로 되돌림. 자가소비는 설치 가능 단가 입력, onsite 는 1구간·2구간 단가를 각각 입력. O&M 포함 필수, 현장 실측 요청, 담당자 연락처·비고 |
| 거래 이력 (2.1.4) | 승인 전까지. 들어온 신청 건수(전체 · 자가소비 · onsite), 표(신청번호 · 기업명 · 계약 유형 · 용량 · 최근 소통 · 상태, 금액 없음), 상태 = 관리자 검토 · 현장 실측 · 조건 협의 · 반려 · 취소(신청하면 바로 관리자 검토, 상태 옆에 단계 번호 n/7). 행 → 한 건 화면: 위 진행 단계(거래 승인과 같은 7단계), 신청 내용(조건 협의 때 관리자가 그 자리에서 고쳐 저장 — 팝업 없음), 진행 이력, 오른쪽 협의 채팅. 관리자: 관리자 검토에서 다음 →(실측 요청 있으면 현장 실측, 없으면 조건 협의) 또는 반려 → 실측 완료 → 조건 협의(입력 · 저장) → 승인. 승인되면 거래 승인으로 |
| 거래 승인 (2.1.7) | 승인된 거래 — 상태: 승인(서명 전) · 전자서명(한쪽 서명) · 체결. 표(신청번호 · 계약번호 · 기업명 · 계약 유형 · 용량 · 계약 기간 · 시작일 · 상태). 행 → 한 건 화면(팝업 아님): 진행 단계, 계약, 서명(관리자: SPC 전자서명 · 기업 서명 확인 / 발전사업자: 전자서명), 계약서(초안/서명본 PDF · 다운로드), 진행 이력 |
| 계약 현황 (2.1.6) | 체결된 최종 계약만, 유형별 건수(표 없음): 자가소비 — 건수·용량 · 예상 설치비 · 연간 O&M / onsite — 건수·용량 · 예상 월 사용량 · 납입료 |
| 내 계약 (2.1.2) | 어떤 계약이 되어 있는지: 요약 · 월별 정산 그래프 · 계약 표(행 → 계약 상세, 신청의 계약 조건 그대로). 계약 상세에서 변경·해지 신청 |
| 변경·해지 (2.1.3) | 자가소비는 O&M 변경(연간 O&M %), onsite 는 단가 변경(1구간·2구간 중 고름), 용량·기간 변경, 해지. 승인되면 계약 조건에 바로 반영 |
| 수익·정산 (2.1.5) | onsite 만(자가소비는 O&M 이 계약에 들어 있어 월 청구 없음). 달이 끝나야 금액이 나오므로 예정 없음 — 작성일 그 달 말일, 발행일 다음 달 1일, 납부 기한 25일. 왼쪽 표(기간 · 기업 · 발전소 · 공급량 · 단가 · 금액), 오른쪽 고른 달(공급자 = 플랫폼, 품목 = 전력 사용, 공급가액 · 부가세 · 합계, 한전 요금 대비 할인액·%, PDF 저장). 거래 수수료 · 망이용료 · 부가정산금은 전력거래소·망을 거치지 않는 onsite 라 없음 |
| 문서 관리 (2.1.8) | 발행되고 받은 문서만: 계약서(서명본) · 청구서 · 세금계산서. 왼쪽 폴더(전체 · 카테고리 · 기업별), 오른쪽 파일 표(즐겨찾기 · 카테고리 · 기업 · 발행일 · 크기 · 보기 · 다운로드). 메일 발송 · 감사 로그 · 공유 없음. 관리자는 문서 등록 |

시드: 체결 = 실제 계약 6건(자가소비 한길 90.88 · 태성산업 46.08 · 건호이엔씨 33.92 · 한일튜브 99.84 · 용인금속 152.32 / onsite 한일튜브 329.6), 나머지 상태는 1건씩 같은 기업·용량·조건으로만 샘플.

사업 구조: offsite·발전사업자 전력 공급 없음. 자가소비는 기업이 설치비를 내고 직접 사용, onsite 는 EPC 가 설치비를 내고 기업은 사용분을 PPA 단가(한전보다 낮게)로 지급 — 절감액 일부는 SPC 로. 계약 상대는 늘 SPC(관리자가 SPC 전자서명). 관리자는 무료진단에서도 기업을 고르거나 신규 기업을 입력해 진단하고, 거래 신청에서 그 기업명으로 불러온다.

데이터는 `src/stores/useTradingPocStore.ts` 한 곳(브라우저 저장). 기업은 실제 대상 5곳(한길·태성산업·건호이엔씨·한일튜브·용인금속)과 데모 로그인 회사만 쓴다 — 에스에너지는 EPC 라 발전사업자로 넣지 않는다.

## 온실가스 인벤토리 (E-데이터마켓 › 온실가스 인벤토리, 2026-10-08)

태양광으로 줄인 탄소(감축량)만 다룬다 — 감축량 = 자가소비 발전량(MWh) × 전력 배출계수. 회사 전체 전력 사용량 · 배출량 · Scope 1 · Scope 3 · CBAM 은 우리에게 데이터가 없어 만들지 않는다. 입력 없이 보기 · 내려받기만, 관리자는 전체 기업(기업별로 나눠), 기업 계정은 자기 회사만. 메뉴 이름은 바꾸지 않는다. 발전량은 데이터 마켓과 같은 값(`generationOf`), 계수는 관리 › 에너지 설정(전력 0.4173 · TOE 0.229 · 소나무 151.5) 한 곳. 계산은 `src/lib/ghg-reduction.ts`, 화면은 `src/components/features/ghg/GhgScreens.tsx`.

| 메뉴 (WBS) | 내용 |
| --- | --- |
| 배출시설 정보 (3.1.1) | 기간(시작 달 ~ 종료 달) · 기업 고르기, 감축량 · 자가소비 발전량 · 화석에너지 대체 · 소나무 식재, 월별 감축량(기업별 쌓기) · 기업별 비중, 기업별 감축 실적 표 |

| 배출계수 관리 (3.1.3) | 에너지 설정 값 보기(계수 · 단위 · 산식 · 기준), 관리자만 [에너지 설정] |

## 디자인 기준

- 색·아이콘·상태 규칙은 `src/lib/design.ts` 한 곳에서 정의한다 (근거: DT WEB 기본 디자인 가이드). 화면은 `src/components/ui/Design.tsx` 의 `SourceBadge` / `SourceIcon` / `StatusBadge` / `MetricIcon` 만 쓴다.
- 배지 글자는 모두 12px. 상태는 네모 + 점 + 글자(`StatusPill`), 분류(초안·출처·구분)는 네모 + 글자(`Badge`). 화면에서 배지 글자 크기를 덮어쓰지 않는다.
- 표 셀 안의 배지는 박스 없이 점 + 글자, 글자 크기는 옆 셀과 같게 — `Design.tsx` 의 `IN_TABLE` 이 자동 처리.
