# ulsan-energy-poc

울산 에너지 자급자족 플랫폼 **POC(껍데기)** — [energy-v2-frontend](https://github.com/routinecrew/energy-v2-frontend) 프론트를 그대로 가져와 백엔드·DB·인증 없이 동작하도록 만든 정적 사이트.

## 특징

- **백엔드 없음**: `src/api/client.ts` 가 네트워크 대신 `src/mocks/poc` 목업 라우터로 응답. 원본 `api/{domain}`·`hooks` 는 수정 없이 사용.
- **로그인 없음**: 로그인 화면의 역할 버튼(전기사용자 / 발전사업자 / 관리자)으로 바로 진입. 이메일을 입력하면 `admin@…`, `operator@…`, 그 외 → 전기사용자로 매핑.
- **정적 export**: `next build` → `./out`. Cloudflare Workers(정적 에셋)로 배포.
- **지도**: 통합관제 지도는 Mapbox GL(`src/components/ui/MapboxMapView.tsx`). 자체 mapbox 구현으로 교체 시 이 컴포넌트만 바꾸면 됨.

## 실행

```bash
npm install
npm run preview    # 운영 빌드 후 http://localhost:3030 — 화면 확인은 이걸로 (빠름)
npm run dev        # 개발 서버 — 페이지마다 첫 진입 시 컴파일하므로 느림(수 초). 코드 수정 중일 때만 사용
npm run build      # ./out 생성
npm run deploy     # build + wrangler deploy (Cloudflare 로그인 필요)
```

> Windows PowerShell 에서는 `&&` 대신 `;` 로 명령을 이어야 합니다. 예: `cd ulsan-energy-poc; npm run preview`

## 전력거래 흐름 (RE100 › 전력거래, 2026-10-02)

통합관제(발전소·용량) → 컨설팅(무료진단 검토) → 전력거래. 메뉴는 기능 WBS 2.1 항목을 **전부** 두고 순서만 업무 흐름대로 바꿨다(항목을 빼지 않는다 — 빼기 전에 사업계획서·WBS 근거 확인). 계약 유형은 자가소비 · onsite 둘 다 신청한다. 상세는 같은 화면 위 창으로 열고 다른 메뉴 화면으로 넘어가지 않는다.

| 메뉴 (WBS) | 발전사업자 `/generator/…` · 관리자(SPC) `/platform/…` |
| --- | --- |
| 거래 신청 (2.1.1) | 계약 유형 카드(자가소비·onsite — 장점과 유의)를 먼저 고른 뒤 입력. 기업은 회원가입과 같은 말(기존 기업 선택 / 신규 기업 등록, 기업명 · 기업 주소) — 고르거나 입력하는 건 관리자만, 그 외는 로그인 값. 같은 유형의 무료진단을 불러오면 설치 용량·계약 기간·요금제·요금 기준·단가·담당자가 채워지고 [불러오기 취소]로 되돌림. 자가소비는 설치 가능 단가 입력, onsite 는 1구간·2구간 단가를 각각 입력. O&M 포함 필수, 현장 실측 요청, 담당자 연락처·비고 |
| 거래 현황 | 신청 진행 상태(접수 → 검토 → 서명 → 체결), 처리 전 취소 |
| 거래 승인 (2.1.7) | 관리자: 신청 검토·승인·반려, 수용가 서명 확인, 변경·해지 승인 / 발전사업자: 승인된 거래 전자서명. 관리자는 설정 › 운영 › 거래 승인(4.3.2, `/platform/trading-approvals`)에도 같은 화면 |
| 내 계약 (2.1.2) | 운영 중 계약만. 계약 상세에서 변경·해지 신청 |
| 변경·해지 (2.1.3) | 변경·해지 신청과 요청 목록 |
| 계약 현황 (2.1.6) | 계약에 관련된 현황만(유형별 건수·용량, 서명 대기·만료 예정·해지, 계약별 기간) |
| 거래 이력 (2.1.4) | 거래한 돈 내역 전부 — 계약별 월 정산(발전·공급량 × 단가 + 부가세), 거래 상대별 |
| 수익·정산 (2.1.5) | 세금계산서 · 청구서 (기존 화면) |
| 문서 관리 (2.1.8) | 계약 문서 조회(계약서·서명본·청구서·세금계산서·합의서·운영 보고서), 행 → 문서 페이지. 관리자는 문서 등록 |

사업 구조: offsite·발전사업자 전력 공급 없음. 자가소비는 기업이 설치비를 내고 직접 사용, onsite 는 EPC 가 설치비를 내고 기업은 사용분을 PPA 단가(한전보다 낮게)로 지급 — 절감액 일부는 SPC 로. 계약 상대는 늘 SPC(관리자가 SPC 전자서명). 관리자는 무료진단에서도 기업을 고르거나 신규 기업을 입력해 진단하고, 거래 신청에서 그 기업명으로 불러온다.

데이터는 `src/stores/useTradingPocStore.ts` 한 곳(브라우저 저장). 기업은 실제 대상 5곳(한길·태성산업·건호이엔씨·한일튜브·용인금속)과 데모 로그인 회사만 쓴다 — 에스에너지는 EPC 라 발전사업자로 넣지 않는다.

## 디자인 기준

- 색·아이콘·상태 규칙은 `src/lib/design.ts` 한 곳에서 정의한다 (근거: DT WEB 기본 디자인 가이드). 화면은 `src/components/ui/Design.tsx` 의 `SourceBadge` / `SourceIcon` / `StatusBadge` / `MetricIcon` 만 쓴다.
- 배지 글자는 모두 12px. 상태는 네모 + 점 + 글자(`StatusPill`), 분류(초안·출처·구분)는 네모 + 글자(`Badge`). 화면에서 배지 글자 크기를 덮어쓰지 않는다.
- 표 셀 안의 배지는 박스 없이 점 + 글자, 글자 크기는 옆 셀과 같게 — `Design.tsx` 의 `IN_TABLE` 이 자동 처리.
- 가이드 페이지: `/guide` (메뉴에 없음, URL 로만 접근). 배포 후 `https://ulsanenergypoc.pairwork.net/guide`.
- 규칙 요약: 발전원 색은 **태양광 노랑 `#F59E0B` · ORC 바이올렛 `#8B5CF6` · 연료전지 파랑 `#3B82F6`** 로 고정(2026-09-22). 화면 아이콘은 lucide(Sun / Flame / BatteryCharging), 지도 핀은 `public/assets/icon/icon_zoom_out_*.svg` 벡터이며 fill 을 `design.ts` 와 같게 유지한다. 상태는 정상 초록·이상감지 빨강 두 가지뿐이고, 지도에서는 이상 발전소의 **핀 자체를 빨강**으로 표시한다(링·펄스 없음). 숫자 KPI 카드에는 아이콘을 붙이지 않는다. 지표는 라벨이 같으면 아이콘도 같다. 퍼센트·이모지는 쓰지 않는다.
- 화면설계서 작성 표준: [`docs/화면설계서-양식.md`](docs/화면설계서-양식.md)
- 표·카드 공통 (2026-10-02):
  - 표(`DataTable`)는 자체 둥근 테두리 없이 카드 안에 일직선으로 붙는다. 카드(`SectionCard`) 본문에 표가 바로 들어가면 본문 여백이 자동으로 없어진다 — 화면마다 따로 맞추지 않는다.
  - 카드 제목 옆 건수 표시("n건")는 쓰지 않는다(카드 컴포넌트에서 뺐다). 목록 행 끝에는 "~에서 보기" 같은 글자 대신 화살표(›)만 두고, 행을 누르면 들어간다.
  - 날짜는 `2026` · `2026-10` · `2026-10-01` 하이픈 양식, 값이 없으면 0 대신 빈칸.
- 버튼 공통 (2026-10-02):
  - 투명 버튼은 쓰지 않는다. `Button` 의 primary · secondary · cancel · danger 는 모두 면이 꽉 찬 버튼이다(ghost 는 아이콘 전용).
  - 뒤로 가기는 앱 전체 `BackButton`(`src/components/layout/PageTitle.tsx`) 하나 — 제목 왼쪽 ← 아이콘, 글자 없음. 오른쪽 '목록으로' 버튼을 두지 않는다. ‹ › 는 날짜·연도·페이지 넘기기에만 쓴다.
  - 단계 이동은 "← 이전" / "다음 →" 같은 화살표 모양.
  - 작성·수정 화면의 취소 · 저장은 제목 줄 오른쪽에 두고, 스크롤해도 상단에 따라다닌다(하단 버튼 줄 없음). 초안 저장 같은 중간 단계 버튼은 두지 않는다.
  - 화면 설명 문장(“~을 고릅니다”, “값을 넣으면 ~” 등)은 쓰지 않는다. 값과 이름만.
