# 화면설계서 작성

## 순서

1. `docs/화면설계서-양식.md` 를 먼저 읽는다. 요소 유형·작성 규칙·예시는 그 파일이 기준이다.
2. 캡처 화면의 page.tsx / PageClient.tsx 를 직접 연다. 메뉴 이름만 보고 짐작하지 않는다.
   - onClick · router.push · Select · Input · mutate 를 찾아 실제로 있는 동작만 쓴다.
   - 권한별 분기(관리자 / 전기사용자 / 컨설턴트 등)도 코드에서 확인한다.
   - 공용 컴포넌트(Button, Badge 등)의 후버 색은 `src/components/ui/` 와 `tailwind.config.ts` 에서 HEX 로 옮긴다.
   - 라우트가 없는 화면은 "미구현"으로 적는다.
3. 캡처와 코드가 다르면(열 이름 등) 코드 기준으로 쓰고 다른 점을 따로 알린다.

## 표기 규칙

- 번호는 캡처에 찍힌 번호를 그대로 따른다.
- 캡처에 번호가 없는 요소는 뒤에 이어 붙이고 "빠뜨린 것 같아서 적어둔다"고 구분한다.
- 서술형 종결(…없다 / …한다)을 쓰지 않고 명사형으로 끝낸다. 예: 없음 · 표시 · 이동
- 셀렉트·탭처럼 고를 수 있는 값은 `기본:` 에 쓰지 않는다. `기본:` 엔 유형만, 선택지는 `상태:` 줄에 슬래시로 쓴다.
- 관리자만 접속 가능한 화면은 1번 앞에 0번 항목을 둔다.

```
0
화면 이름
현재 페이지는 관리자만 접속가능
```

- 오프라인 업무(현장 조치 등)는 넣지 않는다. 넣어야 하면 사용자에게 먼저 묻고 "화면 외 업무"로 구분한다.
- 날짜는 2026-10-01 꼴로 쓴다.

## 전달

- 파일로 만들지 않는다. 채팅에 복사할 수 있도록 코드블록으로 준다.
- 답변은 한국어로 쓴다.
